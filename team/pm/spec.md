# QNote Elec 重构需求规格说明书

**版本：** v1.0  
**日期：** 2026-03-26  
**状态：** 草稿  

---

## 1. 需求概述

对 QNote Elec（Electron 笔记应用）进行项目结构重构和 UI 风格现代化改造，使其目录结构清晰、模块边界明确、跨平台兼容，同时保持核心功能（剪贴板监控、AI 助手 Excalidraw 白板）不变。

---

## 2. 用户故事

| ID | 角色 | 场景 | 期望 |
|----|------|------|------|
| US-01 | 笔记用户 | 使用 QNote 记录日常笔记 | 界面简洁专业，操作流畅，不分散注意力 |
| US-02 | 开发者 | 参与 QNote 开发 | 目录结构清晰，模块边界明确，容易定位代码 |
| US-03 | Windows 用户 | 在 Windows 上使用 QNote | 应用正常运行，窗口控件符合 Windows 习惯 |
| US-04 | macOS 用户 | 在 Mac 上使用 QNote | 应用正常运行，菜单栏和窗口控件符合 macOS HIG |
| US-05 | Linux 用户 | 在 Ubuntu/Fedora 等发行版上使用 QNote | 应用正常运行，窗口行为符合 Linux 桌面规范 |
| US-06 | 剪贴板用户 | 复制内容后希望自动记录 | 剪贴板监控稳定运行，文本/图片自动入库 |
| US-07 | AI 助手用户 | 需要 AI 辅助整理或生成内容 | Deepseek AI 助手响应及时，UI 融入笔记流程 |
| US-08 | 白板用户 | 需要画图或画板辅助思考 | Excalidraw 白板集成流畅，支持保存和加载 |

## 3. 功能需求

### 3.1 结构重构

| 功能点 | 描述 |
|--------|------|
| F-01 | **重构 src 目录结构**：将 renderer/src 和 electron 各自按功能模块（feature）划分，而非按文件类型平铺 |
| F-02 | **分离核心模块**：将 clipboard、notes、ai、whiteboard 等功能拆分为独立模块，定义清晰模块边界 |
| F-03 | **统一类型定义**：将分散在 electron/types 和 renderer/src 中的类型定义统一到 shared/types 目录 |
| F-04 | **规范化配置文件**：统一使用 tsconfig path alias，移除硬编码路径 |

**重构后目标目录结构：**

```
qnote-elec/
├── src/
│   ├── main/                    # Electron 主进程
│   │   ├── index.ts             # 主进程入口
│   │   ├── preload.ts           # 预加载脚本
│   │   ├── core/                # 核心能力（剪贴板、文件等）
│   │   ├── handlers/            # IPC 处理器
│   │   └── utils/               # 工具函数
│   ├── renderer/                # React 渲染进程
│   │   ├── index.tsx            # 渲染进程入口
│   │   ├── App.tsx
│   │   ├── components/          # UI 组件（按功能组织）
│   │   │   ├── clipboard/
│   │   │   ├── notes/
│   │   │   ├── ai/
│   │   │   ├── whiteboard/
│   │   │   └── ui/              # 共享 UI 组件
│   │   ├── hooks/
│   │   ├── pages/
│   │   └── styles/
│   ├── shared/                   # 主进程和渲染进程共享
│   │   ├── types/               # 统一类型定义
│   │   └── constants/
│   └── database/                 # 数据库层
│       ├── index.ts
│       └── migrations/
├── resources/                    # 资源文件（icons 等）
├── build/                        # 构建配置
│   ├── electron-builder.json
│   └── vite.config.ts
└── memory_store/                 # 本地记忆索引（SQLite 表）
```

### 3.2 UI 重构

| 功能点 | 描述 |
|--------|------|
| F-05 | **设计语言统一**：建立 TailwindCSS 设计系统（颜色、字体、间距、阴影），参考 Obsidian/Logseq 的简洁专业风格 |
| F-06 | **侧边栏重构**：重新设计 AppSidebar，统一图标风格，支持折叠/展开，区分主导航和功能区 |
| F-07 | **深色/浅色主题**：实现完善的主题切换机制，支持系统主题跟随 |
| F-08 | **排版优化**：优化编辑器字体、行高、段间距，阅读和编辑体验向 Logseq 靠拢 |
| F-09 | **状态反馈**：统一 loading/error/empty 状态组件，提升用户对应用状态的感知 |

**设计系统关键规范：**

- **主色调**：中性灰 + 单色强调色（参考 Obsidian 的蓝灰调）
- **深色主题**：背景 #1a1a1b，文字 #9b9b9b，卡片 #252526
- **浅色主题**：背景 #fafafa，文字 #383a42，卡片 #ffffff
- **字体**：系统无衬线字体栈，代码使用等宽字体
- **间距系统**：4px 基准网格（4/8/12/16/24/32/48）
- **圆角**：6px 统一圆角，卡片 8px，弹窗 12px

### 3.3 跨平台支持

| 功能点 | 描述 |
|--------|------|
| F-10 | **窗口控件统一**：标题栏使用系统原生窗口控件，移除自定义标题栏，统一三端体验 |
| F-11 | **平台菜单栏适配**：根据平台渲染不同菜单（macOS 菜单栏，Windows/Linux 窗口菜单） |
| F-12 | **路径规范化**：数据存储路径、配置路径使用 platform-compliant 方式（`app.getPath('userData')`、`app.getPath('documents')`），禁止硬编码 |
| F-13 | **构建配置完善**：完善 electron-builder 的 mac（dmg/app）、Linux（AppImage/deb）、Windows（nsis）多平台构建配置 |
| F-14 | **平台特定 API 隔离**：剪贴板监控、文件监听等平台相关代码使用抽象层隔离 |

以下现有功能在重构后**必须保持运行**，不因重构而被破坏：

| 功能点 | 描述 |
|--------|------|
| F-15 | **剪贴板监控**：文本和图片自动捕获入库，支持 OCR 识别 |
| F-16 | **AI 助手**：Deepseek API 集成，支持对话和内容生成 |
| F-17 | **Excalidraw 白板**：白板创建、编辑、保存，加载已有白板 |
| F-18 | **数据库**：SQLite 正常读写，现有迁移脚本兼容 |
| F-19 | **记忆索引**：本地 memory_store 正常写入和召回，无需外部 Python 服务 |

## 4. 非功能需求

| 类别 | 需求 |
|------|------|
| **性能** | 重构后应用冷启动时间不超过 5 秒（以当前未优化版本为基准，不劣化超过 20%） |
| **兼容性** | 向后兼容现有数据库格式，现有笔记数据不丢失 |
| **可维护性** | 模块间依赖关系清晰，无循环依赖；任一模块可独立理解 |
| **可测试性** | 核心模块（clipboard、database、ai）具备可执行单元测试 |
| **可访问性** | 配色对比度符合 WCAG AA 标准（4.5:1） |
| **构建可重复性** | `npm run build` 在三端均可成功构建出可运行安装包 |

## 7. 风险与依赖

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **RT-01**：重构过程中核心功能意外损坏 | 高 | 每个功能模块重构完成后立即执行 AC-13~18 验收；引入自动化测试（优先 clipboard 模块） |
| **RT-02**：跨平台构建在某一平台失败（典型：macOS 代码签名、Linux 依赖缺失） | 中 | 优先完善 Linux/macOS 构建配置；Windows 构建已有基础，风险较低 |
| **RT-03**：TailwindCSS 深色主题实现与现有组件库样式冲突 | 中 | UI 重构前先建立 design tokens，逐步替换而非一次性重写 |
| **RT-04**：electron-builder 多平台构建配置复杂，容易出现"在我机器上能跑"问题 | 中 | 使用 CI（GitHub Actions）在三端分别验证构建产出 |
| **RT-05**：数据库 schema 重构导致旧版本数据不兼容 | 高 | 数据库层作为黑盒处理，只追加不修改已有表结构；提供数据迁移脚本 |

### 外部依赖

| 依赖 | 类型 | 风险说明 |
|------|------|----------|
| **Deepseek API** | 外部服务 | API 可用性依赖网络；若 API 变更可能影响 AI 助手功能 |
| **Excalidraw** | npm 包 | 版本需锁定，避免 breaking change；当前版本 ^0.18.0 |
| **SQLite / better-sqlite3** | 数据库 | native 模块跨平台编译复杂，建议使用 @electron/rebuild 统一编译 |
| **memory_store** | SQLite 表 | 本地存储，依赖现有数据库迁移和召回规则 |
| **electron-builder** | 构建工具 | 需配置多平台 CI 才能完整验证 |

### 项目内依赖

| 依赖 | 说明 |
|------|------|
| electron → renderer | 主进程通过 IPC 控制渲染进程，preload 脚本接口定义后不应轻易变更 |
| renderer → shared | 渲染进程依赖共享类型，需先完成 shared/types 定义 |
| handlers → core | IPC handler 依赖 core 模块，core 变更需同步 handler |
| 数据库迁移脚本 | 必须在首次启动时自动执行，且需向后兼容 |

## 8. 重构范围约定（Out of Scope）

以下内容**不在本次重构范围**内，避免范围蔓延：

- 不新增笔记编辑功能（当前为外部 Excalidraw 白板集成，暂不改造）
- 不改造数据库 schema（只确保现有表可用）
- 不引入外部向量数据库或 Python 嵌入服务
- 不改变应用业务逻辑（剪贴板规则、AI 调用方式等）
- 不新增用户账户系统
- 不改变打包分发方式（仍使用 electron-builder + GitHub Release）
