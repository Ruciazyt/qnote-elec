# pixel-pet

像素宠物生成器。无第三方依赖，PNG 编解码用 Node 内置 `zlib` 手写实现，
克隆下来即可运行，不需要 `npm install`。

## 两套生成器

产物完全同构（同样的帧序、同样的预览排布、同样写 `pet.json`），所以运行时
（`PixelPet.tsx` 的 `ANIM_META`）不需要区分是哪套生成的。

| 生成器 | 入口 | 什么时候用 |
|---|---|---|
| **图片转换**（当前在用） | `src/from-image.mjs` | 有现成的角色图。抠掉背景、降采样、限色、再套动画 |
| **程序化绘制**（回退） | `src/build.mjs` | 没有源图时要画一只新角色。逐像素用代码画 |

```bash
# 当前角色：assets/scarf-dog.png（戴红围巾的小白狗）
node scripts/pixel-pet/src/from-image.mjs

# 回退角色：src/maltese.mjs 里程序化画的马尔济斯
node scripts/pixel-pet/src/build.mjs

# 生成到指定目录
node scripts/pixel-pet/src/from-image.mjs path/to/output
```

两者共用 `src/pet.mjs`（网格常量、动画定义、画布原语、问号浮层）、
`src/png.mjs`（编解码）、`src/pack.mjs`（预览图 + 图集 + pet.json）。

产物：

| 文件 | 用途 |
|---|---|
| `spritesheet.png` | 运行时使用，横向排列的全部帧（1408x64 = 22 帧 x 64px） |
| `pet.json` | 帧索引元数据（每段动画的起始帧、帧数、fps、动作描述） |
| `preview.png` | **校验用**。上排 1:1 真实尺寸（以此判定清晰度），下排 4 倍细节 |

## 换源图（图片转换这条路）

1. 把新图放进 `assets/`，改 `from-image.mjs` 顶部的 `SRC`
2. 跑一次，**先看控制台输出的包围盒和调色板，再看 preview.png**
3. 同步改 `src/renderer/components/core/PixelPet.tsx` 的 `ANIM_LABEL`（读屏文案）

### 这条路上必须知道的三件事

**抠背景不能只用一条阈值。** 手机截图和 QQ 表情导出的图常常没有 alpha 通道，
底色是烤进像素里的。更麻烦的是抗锯齿：轮廓外侧 2~3px 是「角色色↔背景色」的渐变，
里面既有暖的（靠角色那侧）也有冷的（靠背景那侧）。任何单条阈值只能切在一半位置上，
判错的那一半会在成图里变成一圈灰色麻点。所以走两阶段：先取图像四边的高频色当背景参考、
取「确定是角色」区域的高频色当主体参考，再对全图做最近邻判定。
换源图时这两组参考色是自动采样的，不用手改阈值。

**降采样按块内众数，不按平均。** 平均会把描边和白毛糊成一圈灰边；
众数只认块里占比最高的那族颜色，轮廓因此保持锐利。计数时按 5bit 分桶
（每通道 `>>3`）而不是按精确 RGB —— 按精确值计数等于每桶都只有一两个样本，众数会退化成随机取值。

**限色阈值要看真实层次间距。** 源图有五千多种颜色，绝大多数是抗锯齿中间色。
按频次挑主色 + 最小距离去重 + 最近邻吸附，压到 8~10 色。
阈值定太低，抗锯齿中间色会挤进来占掉色板名额（`PALETTE_MIN_DIST = 30`）；
定太高，白毛角色的中间调会被压掉、变成一块平贴纸。

### 版面参数

| 参数 | 作用 |
|---|---|
| `FIT_MAX_W` / `FIT_MAX_H` | 角色在 32x32 格子里的占位上限（当前 23 x 24） |
| `COVERAGE_MIN` | 一格里前景占比低于此值就整格判透明，用来削掉抗锯齿光晕 |
| `PALETTE_MIN_DIST` | 主色间最小 RGB 距离（当前 30） |
| `PALETTE_MAX_COLORS` | 主色数量上限（当前 10） |

占位留出余量是刚需：三个动画都要整体位移，画得顶天立地的话向上 1px 就会被格子裁掉。
改完参数必须跑一次看控制台的贴边告警 —— 格子外的像素是直接丢弃的，
某一帧被裁掉不会报错，只表现为动画循环到那帧时狗忽然缺一块耳朵。

## 加一个角色（程序化绘制这条路）

1. 复制一个角色文件（建议以 `src/maltese.mjs` 为模板）
2. 改 `drawXxx(opt)` 里的图元调用，保持 `outline(cv)` 在五官之前
3. 在 `src/build.mjs` 的 `RECIPES` 里配置帧配方
4. 在 `src/pet.mjs` 的 `ANIMATIONS` 里配置帧数与 fps
5. 在 `src/build.mjs` 顶部换 `drawCharacter` 的导入
6. 跑一次，看 `preview.png`

### 帧配方字段（程序化绘制）

| 字段 | 作用 |
|---|---|
| `bobY` | 身体垂直位移，呼吸用 |
| `capePhase` | 披风/围巾垂片相位，0..5（橘猫角色用 `tailPhase`，摆尾巴） |
| `pose` | 姿态，`null` 坐姿 / `'drag'` 悬空拖拽（见 `maltese.mjs` 的 `POSES`） |
| `swayX` | 整体水平位移，拖拽钟摆用；绘制完成后统一平移画布 |
| `blink` | 闭眼 |
| `squint` | 眯眼 |
| `mark` | 叠加浮层（如问号）的相位 |

### 帧配方字段（图片转换）

| 字段 | 作用 |
|---|---|
| `bobY` | 整体垂直位移 |
| `swayX` | 刚体水平位移 |
| `tilt` | 绕垂直中线的剪切强度，拖拽钟摆用 |
| `mark` | 叠加问号浮层的相位 |

`tilt` 与 `swayX` 一起用才有钟摆感：只平移不剪切，拖拽帧看起来像贴图在滑动，
不像被拎起来晃。图片是拍平的，没法像程序化那样单独控制披风/尾巴，
所以动作全靠整体变换加浮层。

## 加一个动画

1. 在 `src/pet.mjs` 的 `ANIMATIONS` 里加一项（帧数与 fps）
2. 在两个生成器的 `RECIPES` 里加对应的帧数组
3. 在 `src/renderer/components/core/PixelPet.tsx` 的 `ANIM_META` 里加同名的 `start` / `frames` / `fps`

第 3 步的 `start` 必须是前面所有动画帧数的累加值，写错不会报错、只会横向平移。
`background-size` 的总帧数已改为从 `ANIM_META` 求和，不用手动改。

## 改色

程序化绘制：改角色文件顶部的 `PALETTE`，建议 8-16 色，色数不设上限必然出脏。
图片转换：改 `from-image.mjs` 的 `PALETTE_MIN_DIST` / `PALETTE_MAX_COLORS`。

**浅色/白色角色注意**：主白要比 `#FFFFFF` 略暗，体积靠内部阴影而非描边，
预览底色必须是中性灰。详见 `SKILL.md` 的「浅色 / 白色毛色的额外难点」。

## 已知易错点

- **`overlay()` 原地修改并返回目标。** 拿共享的基准帧去 overlay，浮层会永久烧进基准帧，
  之后所有引用它的帧都带上这个东西 —— 表现是「某个状态的装饰出现在别的状态上」，
  不报错、也很难一眼看出是哪一步污染的。派生新帧前先 `clone()`。
- `CELL * SCALE` 必须整除实际渲染尺寸。
- 运行时必须设 `image-rendering: pixelated`。
- `drawQuestionMark` 在 `pet.mjs` 而不是角色模块里 —— 它是通用浮层，两套生成器共用同一份形状。
